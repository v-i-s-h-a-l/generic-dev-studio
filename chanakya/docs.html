Chanakya+Achilles

A two-agent system for managing iOS development

Commands How It Works When to Use Examples File System Tips

Quick Reference

Chanakya — The Strategist

/chanakya Start planning — describe your tasks, get them organized with priorities
/chanakya status See all tasks, their status, blockers, and what's next
/chanakya brief T001 Generate a self-contained brief with Figma context for a task
/chanakya review Diff an updated PRD against existing tasks and flag impact
/chanakya update Sync the master plan with current git and worktree state

Achilles — The Warrior

/achilles T001 Pick up a briefed task — reads the brief, implements, reports back
/achilles Direct mode — describe any task and Achilles executes it immediately

How It Works

You describe work
↓
/chanakya — organizes tasks, assigns priorities
↓
/chanakya brief — fetches Figma, scans code, writes brief
↓
/achilles T001 — reads brief, implements, asks for feedback
↓
Achilles writes debrief to inbox
↓
/chanakya status — processes inbox, updates plan, suggests next

Both agents are proactive — they always suggest the next step. You just say "yes", "no", or redirect.

When to Use What

SituationUse
New feature with Figma designsChanakya + Achilles
Multi-file refactorChanakya plans
Simple bug fixAchilles direct
One-file UI tweakAchilles direct
Crash fixAchilles direct
PRD changed mid-feature/chanakya review
Rule of thumb: If you'd spend more than 2 minutes explaining the task to a worker, use Chanakya to write a brief. Otherwise, go direct.

PRD workflow tips:
• Give Chanakya the PRD file path — it reads the whole doc and extracts requirements per task
• Give all Figma nodes upfront — Chanakya maps them to tasks and fetches during brief generation
• Chanakya catches PRD gaps — ambiguous requirements get flagged before workers hit them
• PRD section refs travel into briefs — workers can trace every decision back to the spec
• Acceptance criteria merge Figma (visual) + PRD (functional) — workers don't cross-reference two sources

Tips

01
Start small
Try /achilles on a bug fix first. Then /chanakya on a small feature. Scale up as you get comfortable.
02
Just say "yes"
Chanakya always suggests next steps. Say "yes" to keep moving, "do T003 instead" to redirect, "I'm done" to stop.
03
Self-selecting workers
Achilles reads the master plan after each task and suggests the next one. You don't need to remember task IDs.
04
Briefs are snapshots
If the codebase changes between briefing and execution, regenerate with /chanakya brief T001.
05
Debriefs are knowledge
Key Learnings in debriefs feed into project memory. Be generous with feedback about what was surprising or tricky.
06
Go parallel
Independent briefed tasks can run in separate terminal tabs simultaneously. They won't conflict.
07
PRD changes are normal
/chanakya review diffs changes against existing tasks and tells you exactly what's affected.
08
Skip when trivial
A one-line crash fix doesn't need Chanakya. Just /achilles and describe the bug.
