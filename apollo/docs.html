What /apollo is

A dedicated iOS performance agent. Diagnoses, fixes, and verifies one metric at a time. Composes with the existing topology — Chanakya dispatches, Achilles applies, Argus reviews. Never replaces them.

Performance work is orthogonal to feature work. Different evidence (Instruments traces, MetricKit payloads, signposts), different review criteria (cohort-aware, regression-aware), different cadence (often retroactive on shipped code). Bolting onto Argus would bloat the reviewer; folding into Achilles would dilute the worker. A dedicated agent with per-metric mode packs matches the lean architecture cleanly.

Status. Memory, thermal, battery, CPU, and measure mode packs are tracked in the router. Each mode keeps its own evidence catalogue and refusal rules.

The strict-9 evidence gate

Apollo's core refusal contract: no fix recommendation without hard evidence. Performance work is full of plausible-sounding fixes that move no needle. Without a forced citation step, recommendations regress to "looks expensive, refactor it" — the worst kind of advice because it generates churn without verifiable benefit.

Auto-capture-before-refuse

Before refusing, Apollo walks the execution-surface decision tree. If a capture path exists and fits the session budget, Apollo captures the artifact itself rather than refuse. Refusal is reserved for when no capture path exists or the budget is exceeded.

Refusal protocol

Every refusal emits a single block in this exact shape:

BLOCKED: <metric> recommendation requires hard evidence; none provided.

Tried to auto-capture via:
  - <path-A>: <reason it failed or was skipped>
  - <path-B>: <reason>

To unblock, capture one of:
  - <artifact-1> — RUN <command>
  - <artifact-2> — RUN <command>

Resume with `apollo <mode> --evidence <path>`.

The --evidence flag is the resumption contract: Apollo accepts a path to the captured artifact and proceeds without re-prompting.

Full contract: apollo/_shared/primitives/evidence-gate.md.

Perf-mode dispatch from Chanakya

Briefs declared with dispatch_agent: apollo route to Apollo instead of Achilles, with perf_mode selecting the diagnostic mode pack and evidence pre-flighting the strict-9 gate at brief-write time. Argus skips these merges entirely (argus/SKILL.md §Skip threshold) — Apollo's re-measure delta on the brief's cohort is the merge gate. Loop spec: apollo/_shared/primitives/perf-merge-loop.md.

Phase 2 modes (deferred)

Launch-time, scroll-perf, binary-size, network-efficiency. Each follows the same per-metric mode-pack pattern. Adding one = one file under modes/, one dispatch row in SKILL.md, one fixture at tests/mode-packs/apollo/<mode>.yaml.

Default behavior

Invoking /apollo with no argument prompts once for one of {memory, thermal, battery, cpu}. Apollo never guesses across metrics — the evidence catalogues diverge and a wrong guess wastes the auto-capture budget.

Host-capabilities contract

Apollo's host node declares installed tools in ~/.dev-studio/.runtime/host-capabilities.yaml. Apollo reads this at boot and refuses to dispatch any mode that depends on an installed: false capability — refusing fast at boot is preferable to refusing mid-investigation with a partially-captured artifact set.

Session budget and deferred capture

Each mode declares a session_budget in frontmatter (default 15 min). When a step would exceed budget, Apollo writes a capture-deferred.yaml row at ~/.dev-studio/<project>/apollo/deferred/<id>.yaml; a scheduled sweep drains the queue when the host is idle. Mode packs cite the deferred id in their refusal block so the user can see what's pending.

Full contract: apollo/_shared/primitives/execution-surface.md.

How Apollo composes

Apollo never writes source files. It measures and recommends; Achilles applies; Argus reviews; Chanakya dispatches and tracks. The boundaries are deliberate — a measurement-first agent that also writes code conflates evidence with implementation.

BoundaryRule
Apollo ↔ AchillesApollo measures + recommends; Achilles applies. Apollo never writes source files in the worktree.
Apollo ↔ ArgusArgus reviews diffs; Apollo verifies the post-fix metric. A recommendation that lands as a PR loops through Argus normally; Apollo's verification is a follow-on capture.
Apollo ↔ ChanakyaChanakya dispatches Apollo on a perf brief or a user-triggered investigation. Findings flow back through the event log; Chanakya files follow-up tasks for the recommended fix.
Apollo ↔ imgly-engine-expertApollo retains measurement + verification authority. Imgly/Metal-specific knowledge routes to the existing imgly-engine-expert skill via the delegation contract at _shared/integrations/imgly-and-metal.md.

Cohort awareness

Every cited artifact names the device class + OS major. A trace from iPhone 12 / iOS 18.6 does not satisfy a recommendation that targets iPhone 16 Pro / iOS 19. This rule is load-bearing: cross-cohort generalization is one of the most common ways perf recommendations go wrong.

Troubleshoot

Apollo refused — what now?

Read the BLOCKED: block. It names the artifacts that would unblock + the exact RUN commands. After capturing one, resume with apollo <mode> --evidence <path>.

Apollo says a tool is "installed: false" at boot

Open ~/.dev-studio/.runtime/host-capabilities.yaml and verify the entry. If the tool is genuinely installed but the file is wrong, fix the file. Apollo refuses fast on purpose — silent capability degradation breaks the strict-9 gate.

The recommendation cites the wrong cohort

The cited artifact's cohort and the targeted cohort must match. Re-capture against the target device class + OS major, then resume with --evidence on the new artifact.

The advisory channel fired but I want a real recommendation

The advisory channel (advisory:1) is reserved for canonical anti-patterns where measurement is structurally impossible. If measurement is possible, the advisory channel is unavailable and Apollo proceeds to auto-capture. Force a capture with /apollo <mode> --capture <workload> (Stage 5 surface).
