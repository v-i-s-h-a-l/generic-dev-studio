What /studio is

A project-scoped router for studio-level operations. Auto-loads when your cwd is inside generic-dev-studio; silent everywhere else. Acts on the studio itself — its rules, releases, plans, machine setup — not on your iOS project.

Not for app code. Implementing features, fixing bugs, reviewing an iOS diff → those route to /chanakya, /achilles, /argus. See chanakya/docs.html.

Quick start

# inside generic-dev-studio:
/studio                   # default → resume the current arc ("where were we?")
/studio review            # walk REVIEW.md against the pending diff
/studio release           # draft release notes per RELEASES.md
/studio audit             # plan ↔ memory ↔ commits drift check
/studio analyze [proj]    # sweep studio-feedback inbox + event logs for <proj>
/studio summary           # end-of-task/session report: done, changed, verified, next command
/studio guard "topic"     # has this work been done before?
/studio work <track>      # run a parallel track, then final reviewed PR + cleanup + summary
/studio work chain workflow-measurement-improvements  # run issue chains with fresh sessions, UUID telemetry, reviewed PRs, cleanup
/studio janitor [--yes]   # cross-project sweep of stale artifacts (dry-run by default)
/studio nodes             # day-2 fleet management — status, add, sync, health, diagnose, schedule, recheck
/studio tf-push [--dry-run] [--background]  # TestFlight push; background returns a run handle for Slack drafting
/studio-setup             # onboard THIS machine (--manager / --worker / --dual; no args → interactive manager)
/studio-help              # open this docs page

Most users type /studio and let intent detection pick the mode. Sub-commands above are also available conversationally — "where were we", "any issues with this diff?", "should we tag?" all route correctly. For unattended track work without the sub-command, start the session with STUDIO_TRACK=<track>.

How it works

It is a thin router. A sub-command or conversational trigger dispatches into one mode pack under modes/, which carries the procedure. The router contract lives in _shared/patterns/router-pattern.md.

When /studio fires

  • Explicit: /studio <mode>, /studio-help, /resume-plan.
  • Conversational: "where were we?", "review this diff", "should we tag?", "audit the arc", "has this been done?".
  • Automatic: hooks/session-start runs the audit mode silently on every session boot — output only when drift is detected.

What it does not do

  • No task dispatch, no worktree management, no build gates, no Slack ingest — that is Chanakya / Achilles / Argus territory. (TestFlight / App Store push is now studio-owned via /studio tf-push; see #217.)
  • No singleton lock, no agent_boot telemetry — studio is a conversational tool, not a fleet worker.
  • No writes outside ~/.dev-studio/<project>/audit/ (audit reports in --report mode). Everything else is read-only chat output + file edits you approve.

PR autopilot

Routine studio PRs run scripts/pr-headless-review.sh <pr>. The script selects a smoke-eligible no-secret reviewer host, captures STUDIO_REVIEW_VERDICT, posts the studio:pr-review-gate comment, and merges only when the verdict is not blocked. The gate records parent host, eligible reviewer profiles, selected reviewer, cross-host status, and fallback attempts. Forge safety-floor PRs add --require-cross-host-when-available; same-host fallback requires --allow-same-host-review --user-approved-bypass <github-url>. Merge cleanup deletes the remote branch and refreshes refs with git fetch --prune.

Commit gate

The repo hook runs scripts/pre-commit-review.sh on the staged diff after local architecture and privacy gates. Only approved and approved_with_fixes allow the commit. User bypass is explicit with STUDIO_BYPASS_REVIEW=1 git commit ... and emits precommit_review_bypassed.

Mode composition

Use /studio <mode> ... + summary when a mode should finish with the standard completion report. This is a reporting composition only; it does not change that mode's writes, gates, or ownership rules.

Tier 1 modes

Shipped today. Each is a mode pack at .claude/skills/studio/modes/<name>.md; the router's dispatch table is the single source of truth for triggers. Every mode has a tests/mode-packs/studio/<name>.yaml fixture per the Phase 2.6.6 skill-testing gate.

/studio resume-plan
"where were we", "pick up from", "/resume-plan"
Loads ROADMAP.md §Phase sequence + ARCHITECTURE.md §Design Vision + pending memory files. Reports current branch, last completed phase, next planned phase, and any deferred questions. Default mode when /studio is invoked with no argument.
/studio review
"review this", "check this", "any issues?", "/simplify" on a studio-repo diff
Walks REVIEW.md rules R1–R11 against the pending diff. Auto-fixes the block+auto-fix tier silently; surfaces ask tier before changing; notes warn tier in the commit message. Scoped to this repo — Turnip diffs go to Argus.
/studio release
"draft release notes", "what's new", "should we tag?"
Consults RELEASES.md for the template and tone rules. Evaluates whether main has crossed a tag-worthy threshold. Drafts outcome-first bullets. Never auto-tags — explicit user go-ahead required.
/studio ingest
"add to parking lot", "file a pattern", "capture this for the studio"
Studio-level capture — patterns observed across projects, rule-tweak proposals, parking-lot entries for an in-flight arc. Strips project-specific identifiers before anything becomes public (GitHub issue, PR description). User-project feedback routes to /chanakya ingest-* instead.
/studio help
"show me the docs", "how does this work?", "/studio-help"
Opens this page in the default browser. Context-cheap — the HTML is rendered by the browser, not loaded into the session.
/studio audit
"audit the arc", "check plan drift" — also auto-runs on SessionStart
Three grep-only probes. A1 decision-ledger consistency (ROADMAP phases ↔ memory pointers). A2 claim-evidence (phases marked ✓ must cite a commit / tag / issue / file path / metric — R10 Iron Law at the plan layer). A3 arc-exit checklist (arcs marked CLOSED must have empty parking-lot and no pending-questions memory files). Silent when clean.
/studio analyze [<project>]
"analyze logs and feedback", "sweep the studio-feedback inbox", "what patterns are showing up?"
Sweeps the studio-feedback inbox at ~/.dev-studio/generic-dev-studio/feedback-inbox/<source>/ + the project's event-log shards (events/*.jsonl, ≥ 2026-04-17). Distinct from ingest (single-input classify); analyze is a queue/log sweep. Detailed citations land in a private report at ~/.dev-studio/<project>/analysis/<today>.md (never committed); scrubbed abstract patterns become GH issues; trivial rule tweaks auto-apply per CLAUDE.md. Surfaces skipped/malformed records explicitly. Strictly studio-only — never falls through to chanakya project queues.
/studio summary
"safe to end session", "what changed?", "wrap this up"
Reusable end-of-task/session report. Checks available evidence, separates automated work from user-pending actions, and reports Done, Changed, Verified, Not Done, Next, and Safe To End. Other modes can compose it with + summary.
/studio work <track>
STUDIO_TRACK=<track> at session start
Autonomous parallel-track loop. Claims the next issue, checks whether the issue is sufficiently shaped, commits each issue to track/<name> without per-issue PRs, then opens one final PR to main. The final PR runs the local review pass plus scripts/pr-headless-review.sh <pr> --method auto; non-blocked reviews merge through the standard autopilot path, clean up the branch/worktree, and finish with /studio summary.
/studio work chain <manifest-or-name>
"run these chains end to end", "fresh session per chain"
Script-backed chain runner for studio issue work. Each chain starts from latest main into a feature branch; each issue gets its own branch, /tmp worktree, fresh host session, issue-run UUID, and required .studio/chain-worker-summary.json. The active session pool scales from healthy registered xcodebuild offload nodes plus local, then clamps by available RAM; completed issue branches rebase and fast-forward into the chain branch in manifest order. The final chain PR runs scripts/pr-headless-review.sh <pr> --method auto, merges only through autopilot, then prunes refs and removes worktrees. Runner telemetry emits chain lifecycle events and writes private reports under ~/.dev-studio/generic-dev-studio/chain-runs/<run_id>/. Dry-run first with scripts/studio-chain-runner.sh workflow-measurement-improvements --dry-run.
/studio guard "<topic>"
"has this been done?", "are we repeating work?"
Before proposing new work, searches three channels. G1 git log + tags (already shipped). G2 memory files (already tried / prior decisions). G3 gh issue list --state all (already in backlog). Surfaces hits separately; user decides continue / merge / drop. Refuses vague single-word queries.
/studio janitor [--yes]
"clean up the studio", "what's reclaimable across projects?", "sweep all projects"
Cross-project sweep of stale artifacts. Fans scripts/sweep-janitor.sh --all-projects all + scripts/fleet-cleanup.sh --all-projects across every project under ~/.dev-studio/. Default is dry-run; --yes applies. Aggregates per-project counts and freed bytes; calls out hot spots > 1 GB. Includes the gap-#31 local-debt pass: merged worktrees, orphan DerivedData, dead-pid xcodebuild.lock. For single-project sweeps, route to /chanakya janitor. Node-side counterpart tracked under #152 (phase-2.7-epic).
/studio nodes
"show the fleet", "list workers", "are the workers up?", "register a worker", "diagnose a worker", "why is dispatch failing?", "sync the workers", "push to workers", "update the workers"
Day-2 fleet management. Default (no arg) renders a one-screen snapshot from configure.sh status + node-health.sh + worker-status.sh. Sub-commands: add / remove <id> / enable\|disable <id> (via configure.sh worker …); health [<id>]; diagnose [<id>] [--role <role>] (via node-diagnose.sh); sync [<id>\|--all] [--dry-run] (via sync-worker.sh / sync-workers-all.sh); schedule on\|off\|status (launchd auto-sync); recheck re-validates the current role against last bootstrap (use after installing Xcode / fixing SSH). Onboarding a fresh machine is not in scope — that goes to /studio-setup. Manifest edits go to scripts/configure.sh manifest.

Auto-propagation (#196): sync automatically merges tools.yaml into the manifest — adding a tool with roles: [worker] propagates on next sync with zero manual manifest editing. Agent directories auto-discover via SKILL.md presence; shim scripts (*-shim.sh) auto-discover via glob. schedule on installs a daily launchd agent so propagation runs unattended.

Tier 2 modes (planned, not shipped)

backlog (GitHub issue triage with privacy scrubbing) and scaffold (generate a new mode pack / primitive skeleton). If a user intent suggests one, the router notes the gap and falls back to the closest Tier 1 mode.

Rulebooks studio modes enforce

Studio is the dispatch layer; the rulebooks are the content. A mode pack walks its rulebook against the situation at hand. Rulebooks are versioned plain-text; when a correction happens, the rulebook is what changes.

REVIEW.md
Repo-specific review rules (R1–R11) the review mode walks against a diff. Covers path-resolver discipline (R3), dual-write preservation (R9), the R10 Iron Law (no completion claim without evidence), R11 no base-branch pushes.
RELEASES.md
When to tag, version math, release-note template and tone. Outcome-first bullets with the user as implied subject. No marketing language, no emojis unless asked.
CLAUDE.md
Project-level conventions: which studio triggers route to which mode, docs-sync rules (what HTML/README surfaces update together), backlog rules (when to open a GH issue), auto-apply tiers (what Claude commits silently vs. asks about), briefing convention, privacy rules for analysis sessions.
ARCHITECTURE.md
Design vision and host-agnosticism principle. Informs resume-plan when re-establishing arc context.
ROADMAP.md
Themed vision + Phase sequence (Completed / Planned / Later + Dependencies). Read by resume-plan and audit.

Install

/studio installs itself. It lives at .claude/skills/studio/ inside this repo; Claude Code auto-loads project-scoped skills when your working directory is in the repo. Fresh clone → /studio is live:

git clone <this-repo> && cd generic-dev-studio
# /studio is already reachable here — try /studio-help

No symlink, no ~/.claude/skills/studio entry. Studio firing outside this repo would be a misfire (it acts on the studio itself; running it against, say, your iOS project has no well-defined meaning).

Installing the rest of the system

The agent layer (Chanakya / Achilles / Argus) is global — installed at ~/.claude/skills/ so /chanakya, /achilles, /argus reach you from any repo. Run the installer once:

./scripts/install.sh            # idempotent — re-run safely after pulls
./scripts/verify-install.sh     # reports any drift

Details in README.md. Agent docs live at chanakya/docs.html.

Extending /studio

Add a new mode pack

  1. Drop a file at .claude/skills/studio/modes/<name>.md with frontmatter (name, description, type: mode-pack, budget_tokens, reads, writes).
  2. Add a row to the dispatch table in .claude/skills/studio/SKILL.md with trigger phrases.
  3. Write a fixture at tests/mode-packs/studio/<name>.yaml — required by the lint gate W_MISSING_PACK_FIXTURE.
  4. Regenerate the capability manifest: ./scripts/capability-manifest.sh --regen.
  5. Update this page and CLAUDE.md's studio-router trigger table.

Add a new audit probe

Audit probes live in scripts/studio-audit.sh. Each probe is a function that calls add_finding <probe-id> <severity> "<msg>" when drift is detected. Keep it grep-only and sub-second — no LLM calls. The probe must calibrate to clean on the current repo state (add evidence to ROADMAP, or tighten the regex, or add memory pointers — do not weaken the probe).

Add a new guard channel

Guard channels live in scripts/studio-guard.sh (probe_g1 / probe_g2 / probe_g3). A new channel needs a grep source (git log, memory, gh, Slack archive, etc.) and a unique label so hits surface separately.

Auto-apply tiers

  • Auto-apply — rule-wording tweaks in REVIEW / RELEASES / CLAUDE, threshold tuning backed by data, brief-template additions, skill-prose trimming, dead-code removal, GH issue creation on explicitly-agreed work, README timeline updates on releases.
  • Ask-first — changing how agents hand off, removing or renaming rules / sub-commands, anything touching runtime behavior in the user's actual project, permission / secrets / auth changes, breaking changes, deleting issues or releases.

Details in CLAUDE.md §Auto-apply tiers. Adaptive trust: if a class of change has zero reverts after five applications, the auto-apply criteria loosen for that class.

Troubleshoot

/studio doesn't appear as a skill in my session.
Studio is project-scoped. It only registers when your working directory is inside generic-dev-studio. If you're in that repo and it's still missing, check that .claude/skills/studio/SKILL.md exists and has valid frontmatter (name, description, type), and that your Claude Code session was started from within the repo.
SessionStart reported studio-audit: drift detected. What now?
Read the findings — each cites a probe (A1 / A2 / A3) and a one-line message. A1 = ROADMAP phases lack memory pointers; A2 = phases marked ✓ without citeable evidence; A3 = an arc is marked CLOSED but its parking-lot or pending-questions memory isn't clean. Fix the underlying state (add evidence to ROADMAP, add a memory pointer, process the parking-lot). Do not silence the probe without fixing the cause.
/studio guard keeps finding noise on my queries.
Vague single-word queries like "fix" or "refactor" will match everything. Use a distinctive phrase ("host-agnostic workers", "auto-sweep backoff"). If all three channels return hits for a legitimate new piece of work, the hits are informative, not blocking — ask whether the new work is distinct, a merge, or a duplicate.
Can I run /studio against my iOS project?
No. Studio acts on the studio — this repo's rules, plans, releases, arcs. For user-project work (implementing features, fixing bugs, reviewing your app's diffs) use /chanakya, /achilles, /argus. Studio's review mode walks REVIEW.md which is specific to this repo's invariants; applying it to app code would be nonsense.
/studio-help says "docs file missing."
The mode resolves the docs path via git rev-parse --show-toplevel + /.claude/skills/studio/docs.html. If that path doesn't exist, something was moved or deleted. Re-run git status to see what's changed; docs.html should be checked in.
I added a new mode and the linter says W_MISSING_PACK_FIXTURE.
Every mode pack must ship a fixture at tests/mode-packs/studio/<name>.yaml. See _shared/primitives/skill-testing.md for the schema. The linter gate is load-bearing; do not disable it.
Audit drift report writes under ~/.dev-studio/ — is that right?
Yes. Audit reports are per-project private artifacts resolved via scripts/lib-paths.sh's resolve_audit_root. They're never committed. Runtime writes live under ~/.dev-studio/<project>/ by R3; audit reports follow the same rule.
