# Phase 2.5 Execution Plan (locked)

Drafted and locked 2026-04-20 for the `refactor/intent-router` branch. Every design decision below is **locked** unless explicitly marked deferred. Deferred items have a tracking home (GitHub issue link added when issues are opened post-plan-rewrite).

See `ROADMAP.md` §Phase sequence for phase context. This phase is foundational — 2.6, 2.7, 3+ all land on top of the contracts, schemas, and primitives defined here.

## 0. Standards and non-negotiables

These govern every decision in this plan and every later phase that builds on it:

- **World-class — fit-for-purpose at this project's scale, not fit-for-enterprise.** Single-user workflow tool on a personal laptop where the real work is iOS development. Reliable, observable, light at runtime, zero recurring costs, no heavy local dependencies (no resident LLMs, no multi-GB dbs, no paid APIs). Phase work vertically (ship a small slice perfectly), never horizontally (wide fragile layer). See memory: `feedback_world_class_standard.md` (updated 2026-04-20 with scope qualifier).
- **Agent-first design.** The studio is built for agent-to-agent orchestration; human involvement is the exception. Optimize for consistent shapes, machine-readable outputs, zero interactive prompts. Agent-consistency bugs (drift across model versions, prompts, agent boundaries) are the error model we invest against — not human typos. See memory: `feedback_no_manual_input.md`.
- **Three-tier artifact paths.** Tier 1: design artifacts committed to repo tree. Tier 2: per-machine runtime under `~/.dev-studio/<project>/`. Tier 3: multi-machine reconciled state under `~/.dev-studio/<project>/shared/<machine-id>/`, append-only partitioned-by-writer. Non-negotiable. See memory: `feedback_artifact_paths.md`.
- **Minimal permission footprint.** Everything resolves through `scripts/lib-paths.sh`. No writes outside the three tiers. No new allowlist asks.

## 3. New primitives (2.5 deliverables)

### 3.1 `contracts/message-contract.md`

Canonical envelope for every inter-agent message (brief, debrief, review verdict, event, snapshot handoff):

| Field | Type | Notes |
|---|---|---|
| `schema_version` | `{name, version, min_reader, deprecated_at}` | Per Q10. |
| `message_id` | UUIDv7 | Monotonic, timestamped. |
| `correlation_id` | UUIDv7 | Inherited across task lifecycle. |
| `idempotency_key` | string | `<agent>:<mode>:<stable-subject>:<content-hash>`. |
| `producer` | `{agent, mode, instance_id, version}` | Agent-drift guard per Q12. |
| `recipient` | `{agent, version_range?}` \| `"broadcast"` | |
| `intent` | enum | `request` / `response` / `event` / `handoff` / `cancel`. |
| `payload_schema` | string | Points at file in `schemas/`. |
| `payload` | object | Validated against `payload_schema`. |
| `reply_to` | `message_id`? | For responses. |
| `occurred_at` | RFC3339 UTC | |
| `reads[]` | `[path]` | Declared read surface. |
| `writes[]` | `[path]` | Declared write surface. |

Transport-agnostic: filesystem today, possibly iMessage/Telegram/HTTP later. Envelope doesn't change.

### 3.2 `contracts/idempotency.md`

1. Every writable action idempotent on `idempotency_key`.
2. Key construction: `<agent>:<mode>:<stable-subject>:<content-hash>`.
3. Duplicate detection: producer checks sink tail for matching key pre-write. If found, emit `action_deduped` event and no-op. **No locks.**
4. Retries MUST reuse the original key.
5. Event log: best-effort append (Q12) — readers dedupe via shared primitive, not write-time checks.
6. Partial-failure: retry with same key = no-op ack, never double-write.

### 3.3 `contracts/schema-version.md`

Every YAML / JSON / message carries:

```yaml
schema_version:
  name: "brief"
  version: "3.1.0"        # SemVer: major=breaking, minor=additive, patch=fix
  min_reader: "3.0.0"     # readers below this version must reject
  deprecated_at: null     # RFC3339 timestamp when this version will be retired, or null
```

Readers that don't meet `min_reader` reject loudly, never silently degrade. Deprecations announced via `deprecated_at` so consumers can upgrade before hard-break. Schemas live in `schemas/<name>.md` with a history table.

### 3.4 `contracts/event-emission.md` (new — split from chanakya-principles)

The event-emission boilerplate (format, producer tagging, idempotency keying for events) extracted from `chanakya-principles.md` into its own contract doc. Referenced by every mode pack that emits events.

### 3.5 `contracts/read-write-decls.md`

### 3.6 `state-machines/task-lifecycle.md`

States: `proposed → briefed → dispatched → in-progress → self-reviewed → argus-reviewed → merged → user-verifying → verified | rejected → archived`. Side states: `blocked`, `cancelled`, `requeued`.

Key transitions:
- `briefed → dispatched` requires `brief@>=2` present + worker idle marker.
- `in-progress → self-reviewed` requires debrief written.
- `self-reviewed → argus-reviewed` requires Argus verdict event; bypass only with `xs-diff` exemption.
- `argus-reviewed → merged` requires `verdict ∈ {approved, flagged}`.
- `rejected` → `briefed` with `rework_of: <task-id>`.

Each transition emits event with `from_state`, `to_state`, `actor`. Mermaid diagram included.

### 3.11 `patterns/dry-run.md`

1. Mode performs reads and computations normally.
2. Writes replaced by log line: `DRY-RUN write path=<path> bytes=<n> idempotency_key=<key>`.
3. Events buffered and printed, not appended.
4. Exit code: 0 = would succeed; 2 = dry-run surfaced a problem.
5. Additive flag, never inverts defaults.
6. Router prose enumerates non-write modes inline.

**2.5 pilot (Q6):** Achilles `task` mode implements `--dry-run` end-to-end. Contract bugs discovered there get fixed before 2.6 rewrites apply the pattern to 30+ modes.

### 3.12 `patterns/budget-telemetry.md`

- New event `mode_budget_exceeded` when session total > 1.1× budget.
- `scripts/budget-report.sh` aggregates daily/weekly; wired into compact mode.

### 3.13 `patterns/multi-machine-sync.md` (new — Q9 upgrade)

Tier-3 contract for multi-machine reconciled state. Enshrined now so no later phase lands a fragile shared-mutable-state shortcut.

**Rules (non-negotiable):**
1. Partitioned by writer: every writer owns `~/.dev-studio/<project>/shared/<machine-id>/`. No writer touches another writer's partition.
2. Append-only within partitions. No in-place updates. Atomic rename-new-file for files that look mutable from outside.
3. Merge semantics at read-time: union all partitions, stable order by `(occurred_at, machine-id)`.
4. Conflict-free by construction. No locks, no CRDTs, no coordination.
5. Sync mechanism (git repo / rsync / S3 / etc.) pluggable — any mechanism that preserves partition integrity works.

**Primitives shipped in 2.5:**
- `scripts/machine-id.sh` — stable UUID per machine, written once to `~/.dev-studio/.runtime/machine-id`.
- `scripts/write-shared.sh` — routes logical path into self-partition, append-or-atomic-rename.
- `scripts/read-shared.sh` — enumerates partitions, merges per contract, returns stream.
- Directory skeleton created lazily on first write.

**Sync mechanism — chosen (2026-04-20):** Private GitHub repo. Each machine pushes its own `shared/<machine-id>/` partition; pulls others. Append-only model maps cleanly to git commits on a shared `main` branch — no conflicts because partitions never overlap. Works asymmetrically (either machine can be offline; other catches up later). Free (private repos unlimited). The Mac mini offload scenario (see memory `project_mac_mini_worker.md`) is the first real user; initial staging is tests-only, escalating to builds + uploads as credentials get provisioned.

**SSH + rsync** over LAN/Tailscale may land later as an additional low-latency same-LAN mechanism without breaking the contract (both machines online, skip git roundtrip). Not required for 2.5.

**Deferred:** first mode-pack consumer of tier-3 (no mode writes through `write-shared.sh` in 2.5). See §8.

### 3.14 Event-log producer tagging (Q12 simplified)

Every event carries `producer: {agent, mode, instance_id}` and (when applicable) `idempotency_key`. Writing these fields is mandatory — cheap, observable, and required for any future dedupe. **Reader primitive deferred** (see §8): single-user serial workflow rarely produces duplicates. If/when one appears, a ~50-line `scripts/read-events.sh` wrapper lands then. Contract (`contracts/events.md`) already specifies the dedupe rule `(producer.agent, idempotency_key)` so any ad-hoc consumer can apply it correctly.

## 4. Linter extensions — 3 new codes (trimmed 2026-04-20)

Right-sized to the scale of ~30 mode packs authored by one person. Dropped two codes that would add friction without catching real bugs at this scale. Remaining codes land as warn-only first (`ARCH_LINT_LEVEL=strict` gate), promoted to block after a 48h soak.

| Code | Tier | When | Fix recipe |
|---|---|---|---|
| `E_MISSING_RW_DECL` | block | A `modes/*.md` lacks `reads:` or `writes:` keys | Add `reads: []` / `writes: []`. Routers exempt (synthesized automatically). |
| `E_UNKNOWN_CONTRACT_REF` | block | Reference to `_shared/<subdir>/<file>` that doesn't exist | Move/rename or fix the reference. Linter holds index of `_shared/**/*.md`. |
| `W_CAPABILITY_STALE` | warn (permanent) | `capability-manifest.json` older than any staged `modes/*.md` | Run `scripts/capability-manifest.sh --regen`. **Never promoted to block** — user reads warnings during analysis sessions and regenerates intentionally. |

**Dropped (right-sizing):**
- `E_SCHEMA_VERSION_MISSING` — for ~10–20 schema files authored by one person, block-tier is over-enforcement. `git grep schema_version` on review catches real omissions.
- `W_IDEMPOTENCY_UNSPECIFIED` — self-written mode-pack docs, self-understood semantics. Re-add only if real drift surfaces.
