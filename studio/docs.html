Generic Dev Studio

A three-agent orchestration system for Claude Code — Chanakya plans, Achilles writes, Argus reviews.

Built around iOS/SwiftUI. Orchestration layer is stack-agnostic.

What it is

Generic Dev Studio turns Claude Code into a small team. You talk to one agent in plain English; it decomposes the work into briefs, hands them to a worker that codes in an isolated git worktree, and routes the diff through a reviewer before anything merges back to your branch. Your uncommitted changes never get touched.

Three ideas hold it together:

  • Routers, not monoliths. Each agent's SKILL.md is a thin dispatcher (<100 lines) that loads a mode pack on demand. You pay context cost only for the mode you need.
  • File-based IPC. Briefs, debriefs, events, tasks — all plain files under ~/.dev-studio/<project>/. Claude restarts, laptop sleeps, power blips — the state survives.
  • Rulebooks that future sessions auto-pick-up. REVIEW.md, RELEASES.md, ARCHITECTURE.md live at the repo root. A new session reads them as a matter of course, so the conventions hold.
Who is this for? One developer running Claude Code locally who wants to fan work out across multiple agents without babysitting each one. It is not a CI system, not a hosted service, and not a replacement for human code review on anything shipping to users.

The three agents

Each agent has a narrow job and its own skill directory. Mode packs live under <agent>/modes/; the SKILL.md router picks one per invocation.

Chanakya
PM / orchestrator (singleton)

Turns a feature description into prioritized tasks with IDs, writes self-contained briefs (Figma specs, codebase pointers, acceptance criteria), sweeps the inbox, tracks debt, and drives the user-verification pipeline.

  • /chanakya status, brief, ship, sweep
  • test-manifest, test-flow, review-feedback
  • Slack ingest, feedback archive, reporting
Achilles
Implementer (many concurrent)

Reads a brief, implements in an isolated worktree, self-reviews, gates on a green build, invokes Argus pre-merge, merges back, and drops a debrief. XS/S tasks skip xcodebuild and accumulate build debt.

  • /achilles T001 — task mode
  • /achilles build — on-demand build check
  • /achilles debrief — capture an in-chat fix
  • /achilles worker — fleet pane
Argus
Reviewer (two-stage)

Runs between Achilles self-review and merge. Stage 1: does the diff match the brief? Stage 2: cross-file regression, edge cases, secrets, staleness, tests. Stage 2 only fires if Stage 1 is approved or flagged.

  • Auto-invoked by Achilles pre-merge
  • /argus / /argus T001 standalone
  • XS-trivial diffs skip Argus entirely

Planned roster: Lu Ban (architect, greenfield designs → ADRs) and an Argus smoke mode that folds synthetic-QA in without adding a fifth agent.

The studio router

The agent routers above handle task-level work on your project. The studio router is different: it handles operations that concern the studio itself, or that cut across agents. Invoke it by intent — if you say "where were we" or "review this", the studio router picks the right mode.

Tier 1 modes (shipped today)

/studio resume-plan
"where were we", "pick up from"
Loads ROADMAP §Phase sequence + ARCHITECTURE §Design Vision + pending memory, reports current branch / last phase / next phase, asks any deferred questions.
/studio review
"review this", "check this", "any issues?"
Walks REVIEW.md against the pending diff. Auto-fixes the block+auto-fix tier silently, surfaces ask-tier before changing, notes warn-tier either way.
/studio release
"draft release notes", "what's new", "should we tag?"
Consults RELEASES.md, evaluates whether the repo has crossed a tag-worthy threshold, drafts outcome-first notes. Never auto-tags — always waits for explicit go-ahead.
/studio ingest
"add to parking lot", "file a pattern"
Studio-level capture outside Chanakya's inbox — patterns, analyses, rule-tweak proposals, parking-lot entries. Strips project-specific identifiers before anything becomes public.
/studio help
"show me the docs", "how does this work?"
Opens this page. Also runnable as the /studio-help slash command.

Tier 2 modes (planned)

backlog (gh issue triage), audit (architecture audit run), scaffold (new mode pack / primitive skeleton). Not shipped today; if your intent suggests one, the router notes the gap and falls back to the closest Tier 1.

Don't dispatch through /studio for task work. Implement X, fix bug Y, review a Turnip diff — those route to /chanakya, /achilles, /argus directly. The studio router is scoped to operations concerning the studio itself.

Rulebooks

Five files at the repo root are authoritative for how the studio behaves. They are not docs; they are rules a session reads before acting.

REVIEW.md
Review-time rules (R1–R11) with tiers — block+auto-fix, ask, warn. Walked against any diff that touches scripts/*.sh, SKILL.md, _shared/*, or exceeds 100 lines. Walked before committing, not after.
RELEASES.md
When to tag, how to version, release-note template, tone rules. Outcome-first bullets with the user as the (implied) subject. No marketing language, no emojis unless asked. Every MINOR has a headline feature.
CLAUDE.md
Project-level conventions: studio router triggers, review/release/docs-sync/backlog rulebooks, auto-apply tiers (what Claude commits silently vs. asks about), briefing convention, privacy rules for analysis sessions.
ARCHITECTURE.md
Design Vision (2026-04-20 synthesis), agent roster, rejected alternatives, §Host-agnosticism principle. Load-bearing for any cross-cutting architectural decision.
ROADMAP.md
Phase sequence with dependencies (what's done, what's next, what's parallelizable). Paired with GitHub issues for actionable backlog. Themes live in THEMES.md.

Common workflows

From a feature idea to a merged change

/chanakya                        # describe the feature → master plan
/chanakya brief T001             # self-contained brief with Figma + code pointers
/achilles T001                   # isolated worktree → build → Argus → merge
/chanakya status                 # what's in flight, what needs verification

Fan out to multiple workers

# In N iTerm panes, Cmd+Opt+I to broadcast-type:
/achilles worker                 # each pane atomically claims a slot
# Then in your Chanakya pane:
/chanakya ship T001,T002,T003    # auto-routes to idle workers

Quick in-chat bug fix (no brief, no worktree)

# You describe the bug, Claude fixes it inline, then:
/achilles debrief                # capture the fix as a YAML debrief
                                 # (no Argus, no master-plan task)

Review before commit

# Say "review this" or invoke /simplify on the pending diff.
# Studio router walks REVIEW.md:
#   - block+auto-fix tier    → Claude fixes silently, commits with the diff
#   - ask tier               → Claude surfaces, waits
#   - warn tier              → Claude notes both in chat and commit msg

Drafting a release

# After a few tag-worthy commits land on main:
# Say "should we tag?" or "draft release notes"
# Studio router consults RELEASES.md → drafts outcome-first notes
# You review, say "tag it" → git tag + gh release create
# Then README.md Mermaid timeline + Story so far auto-updates

Resume after a break

# /resume-plan  — or just say "where were we"
# Loads ROADMAP §Phase sequence + ARCHITECTURE §Design Vision
# + any project_*_pending.md memory
# Reports current branch, last completed phase, next planned phase.

Tips — get the best out of it

Do

Let Claude auto-apply silently. Rule-wording tweaks, README clarifications, issue creation on agreed work — these are auto-apply-tier in CLAUDE.md. Approving each one is friction; revert if wrong.

Don't

Don't dispatch through /studio for task work. Fixing a bug, implementing a feature, reviewing a Turnip diff — those go to /chanakya, /achilles, /argus. Studio is for cross-cutting or studio-itself ops only.

Do

Prefer the brief-then-ship flow for non-trivial work. /chanakya brief T001 → /achilles T001 gives Achilles a self-contained context. Direct-to-Achilles works for quick changes; briefs scale better.

Don't

Don't write TODOs casually. Tracked deferrals use TODO(#42): with an issue reference. Anything else belongs in a GitHub issue or the code itself, not a comment.

Do

Walk REVIEW.md before committing, not after. Findings land in the commit message and in chat. Retroactive reviews are a failure mode — the rules exist to shape the commit, not audit it.

Don't

Don't hand-roll runtime paths. Every script resolves paths via scripts/lib-paths.sh. Hardcoding ~/.dev-studio/turnip-ios/... is a REVIEW R3 block.

Do

Use /chanakya studio-feedback to improve the studio itself. Friction you hit becomes a canonical feedback record; the next generic-dev-studio session ingests it. This is the intended upgrade loop.

Don't

Don't leave worker panes open indefinitely. Between sessions run scripts/fleet-cleanup.sh (soft) or --all (full teardown). Stale locks eventually cause dispatch oddities.

Minimal-intervention philosophy

The studio is designed for unattended runs. Claude should not stop to confirm routine work. It pauses only at: Slack publish, first-time config writes, merge conflicts, and explicit --wait feedback windows. If you see a permission prompt mid-automation, something is off — usually a path escaping ~/.dev-studio/**. File it as studio feedback.

Token budget

Mode packs load on demand, so a dispatch pays only for what it dispatches. Snapshots under ~/.dev-studio/<project>/.runtime/snapshots/ pre-warm Chanakya's status views. Away-mode caps MCPs and disables scheduled wakes. Argus scopes cross-file scans (10 neighbors × 50 lines) and caps diffs at 500 lines. None of this is a knob you normally touch — good defaults.

Paths

All runtime state lives outside ~/.claude/ so neither agent trips self-mod prompts. Two roots:

RootScopeContains
~/.dev-studio/<project>/ Per-project plans, worktrees, inboxes, debriefs, events, snapshots, locks
~/.dev-studio/.runtime/ Machine-global shared machine resources (test-slot semaphore, cross-project fleet view)

The <project> slug defaults to the git toplevel basename; override with ACHILLES_PROJECT=<slug>. Scripts resolve paths via scripts/lib-paths.sh — never hardcode.

Extending the studio

Add a new mode pack to any router

  1. Drop a file under <agent>/modes/<name>.md with frontmatter (name, description, type: mode-pack, budget_tokens, reads, writes).
  2. Add one dispatch row to the agent's SKILL.md table.
  3. Add a fixture at tests/mode-packs/<agent>/<name>.yaml with scenario, failure_signals, success_signals. Required by the Phase 2.6.6 gate — without it the linter emits W_MISSING_PACK_FIXTURE.
  4. Run scripts/test-mode-pack.sh <agent>/<name> to validate.

Add a new _shared primitive

Live under _shared/{patterns,contracts,state-machines,schemas,primitives,rules}/. A primitive earns its own file when at least two agents or two mode packs reference the same behavior. Prefer linking to a primitive over copy-pasting prose — the architecture linter catches duplicated prose past a Jaccard threshold.

Add a new slash command

Thin wrappers go under commands/ (installable via symlink) or .claude/commands/ (project-local). Wrappers should forward to a mode pack, not duplicate its steps.

Add a new script

All scripts MUST resolve paths via scripts/lib-paths.sh, be both bash and zsh compatible, and pass bash -n. Register in the surface manifest via scripts/update-surface-manifest.sh. If the script emits events, use scripts/emit-event.sh — don't hand-roll JSONL.

Automation tiers (what Claude does silently vs. asks about)

  • Auto-apply — rule-wording tweaks, threshold tuning backed by data, brief-template additions, skill-prose trimming, dead-code removal, GH issue creation on agreed work, README roadmap updates on releases.
  • Ask-first — changing how agents hand off, removing/renaming rules or sub-commands, anything touching runtime behavior in the user's actual project, permission/secrets/auth changes, breaking changes, deleting issues or releases.
  • Hard stop — auto-apply never touches the user's project's runtime behavior. Their project is sacred; the studio's conventions are negotiable.

Troubleshooting

Permission prompts mid-automation — what did I do wrong?
Usually a path escaping ~/.dev-studio/**. Check the offending script for hardcoded ~/.claude/, /tmp/, or $HOME writes. All runtime writes must land under ~/.dev-studio/; that root is pre-allowlisted. File as studio feedback so the router doesn't regress.
A worker pane is stuck busy but nothing is running.
Stale lock. Run scripts/fleet-cleanup.sh (soft sweep clears stale locks, old done/, rotates large logs) or --all for a full teardown — the latter refuses if any worker is still alive. The lock format is mkdir + PID-token, so a recycled PID won't steal the slot.
Achilles finished a task but it never showed up in /chanakya status.
Orphan debrief — the task completed but slipped the master plan. Run scripts/backfill-orphan-debriefs.sh (dry-run default) to see; add --apply to fix. Also surfaced as an inbox_sweep_completed count in the next sweep.
Argus keeps flagging stale-base merges.
Achilles Step 8.4 runs scripts/achilles-refresh-base.sh pre-Argus, which fetches and merges base; stale-merge blocks usually resolve in-flight. If they persist, check for merge conflicts that need manual resolution, then re-run Argus.
How do I pause Argus for a task?
scripts/waive-start.sh argus "<reason>" "<sunset_trigger>" — opens a structured pause with an accumulated-skip counter surfaced in the SessionStart banner. Lift with scripts/waive-lift.sh argus. Waives are visible by design; they shouldn't be quiet.
SessionStart bootstrap didn't fire — context looks empty.
The hooks/session-start Claude Code hook injects router-bootstrap context on startup|resume|clear|compact. If it's missing, verify the hook is registered in ~/.claude/settings.json and the path is correct. A fallback prose-preamble is on the Phase 2.6.6 roadmap.
Event log day rolled over mid-sweep — will I lose state?
No. The offset marker is a (filename, byte) tuple, so Chanakya re-reads the new day's file from 0 when the byte offset exceeds the new file size. Atomic rotation is safe mid-read.
